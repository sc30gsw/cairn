# Mantine 9.6 UI 改善と採用候補

2026-09-09。Mantine 9.6.0 の[公式変更履歴](https://mantine.dev/llms/changelog-9-6-0.md)と現行実装を確認し、独立した2案を best-of で比較した。

## 合意した方向

現在の Paper Redesign の雰囲気を保ち、情報の見やすさと操作性を改善する。他ページで使える機能や追加するとよい UI も評価する。色・フォント・紙の形状は既存トークンに従う。

「ボード」は実行ボード、「積み重ね通知」は操作直後のトースト、「Stepper」はホームのセットアップを対象とする。[CONTEXT.md](../../CONTEXT.md) の通知欄・トースト・セットアップの定義は維持する。追加機能で合意した学習量の平均とゴミ箱の復元規則は、用語集にも採用計画として記す。今回の変更には ADR を追加しない。

## 実装済みの改善

- 既存の `@mantine/*` 9パッケージを 9.6.0 に統一する。未使用パッケージは追加しない。
- カンバンの状態名・件数・計測時間を分け、空列の領域と移動先を見分けやすくする。操作不可時はドラッグ開始も止める。状態遷移、分数入力、保存順序、モバイルのメニュー操作は維持する。
- アプリ共通の `Notifications` に `layout="stacked"` を設定する。上端中央と safe area の調整は維持する。ベルの通知履歴は別の機能。
- セットアップの横並びに `labelPosition="bottom"` を使い、狭い領域は縦並びにする。「完了」は実際の設定状態で決め、「あとで設定」を完了として扱わない。後の手順を先に完了した場合も正しく表示する。
- 年表示の既存 `renderDay` を継続し、日ボタンから予定一覧を開けるようにする。既存のホバープレビューに加え、タップやボタンのキーボード操作で開き、Escape・閉じるボタンで閉じられる。月外の日を重複表示しない。

2案とも、この範囲を優先し、新しい DND 基盤や全体リデザインは不要との結論だった。レースは設計案の比較であり、実装済み画面を2種類制作した比較ではない。

| 比較案 | 結果 | 採用の根拠 |
| --- | --- | --- |
| A | PASS | 列見出し・空列・ドラッグ先の改善と、セットアップの実状態による完了判定を提案 |
| B | PASS | 同じ優先順位を独立に確認し、下配置ラベルのレスポンシブ化と年表示の入力方法の偏りを指摘 |

離脱なし。選定方式は best-of。両案の一致した改善を採用した。追加の相互レビューで、ホバー後のクリック選択から閉じた際のフォーカス復帰を修正し、回帰テストを追加した。コメント監査は指摘0件、削除・復元・制約の符号化・未解決はいずれも0件。

## YearView.renderDay を使うべきか

**実行ボードの年表示では継続使用が適切。すでに使用している。** 日番号・予定の色印・予定一覧のプレビューを組み合わせる現行用途に合う。Mantine の日ボタンがキーボードナビゲーションを担当し、`renderDay` は中身を描く。内部に別の日ボタンを置かない。

`renderDay(date, dayEvents)` のイベント配列には3件の上限がない。予定が多い日には「+件数」の表示を加える余地がある。履歴の学習量ヒートマップは実績、年表示は予定なので、同じカレンダーに見えても置き換えない。週末にも学習するため `withWeekendDays={false}` は採用しない。

## 追加機能の採用計画

以下は対話で選んだ追加機能の計画であり、実装には未着手。既存のデザインを保ち、履歴・方法カタログ・ゴミ箱を改善する。実装順は次のとおり。

| 順序 | 採用する機能 | 画面と目的 |
| --- | --- | --- |
| 1 | Charts の週末・選択日の注記 | 履歴の週・月の日別ペースを読みやすくする |
| 2 | RichTextEditor の折りたたみ | 方法カタログのメモで長い例・補足を畳む |
| 3 | ActionBar の一括復元 | ゴミ箱の日と記録をまとめて戻す |
| 4 | MatrixChart | 履歴の週・月で曜日ごとの学習内容と平均分数を比較する |
| 5 | Schedule の移動・リサイズ間隔 | 実行ボードの日・週表示で時間付き予定を15分刻みに調整する |

### 1. 履歴グラフの注記

週・月の日別ペースに `referenceAreas` で薄い週末帯を加え、`referenceDots` で選択日の確定分数を示す。帯と点には意味が分かる凡例を添える。既存の合計・移動平均・数値表と、日を選ぶ操作は引き継ぐ。選択日が表示範囲の外にある場合や値がない場合は点を出さない。0分と値なしは区別する。

既存の日付・確定分数・選択日だけで描画できる。取得内容を増やす必要はない。主な変更先は [HistoryAnalysisPanel](../../src/features/history/components/analysis/history-analysis-panel.tsx) と [chart-data](../../src/features/history/lib/chart-data.ts)。

### 2. 方法メモの折りたたみ

対象は方法カード編集モーダルのメモ欄。ツールバーに折りたたみの挿入・解除を加え、見出しと補足本文を編集できるようにする。カードを開くたびに閉じた状態から始め、その場で開いて編集する。開閉ボタンには日本語の名前と状態を付け、キーボードでも操作できるようにする。

Tiptap の `Details`・`DetailsSummary`・`DetailsContent` を登録し、[`persist: false`](https://tiptap.dev/docs/editor/extensions/nodes/details) で開閉状態を保存しない。追加依存は `@tiptap/extension-details` とし、インストール済み Tiptap と整合する版を Vite+ 経由で追加する。公開後24時間の依存ポリシーを守る。

既存の手動保存と HTML 形式を継続する。Formisch＋Valibot はタイトル・本文を管理し、メモと完了条件の editor 値は保存時に合流する。タイトルは必須、それ以外は空を許可する。保存失敗時は編集内容を保持し、閉じた場合の未保存内容は既存どおり破棄する。本文は textarea、完了条件はタスクリストのままとし、メモの折りたたみだけを追加する。

主な変更先は [MethodCardModal](../../src/features/methods/components/method-card-modal.tsx)。既存のリンク・箇条書きと折りたたみが保存・再表示・再編集を通して失われないこと、SSR 初期描画で editor の不整合が起きないことを確認する。

### 3. ゴミ箱の一括復元

現在の日・記録の2つの一覧にチェックボックスと全選択を加える。対象を選んだときだけ ActionBar を表示し、「日 N件・記録 M件」「選択解除」「まとめて戻す」を置く。現行一覧にはページングや絞り込みがないため、全選択は表示されている一覧全体を対象とする。日と記録は別々に数え、親の日を重複して数えない。

記録の親の日が削除されていたら、必要な親の日を選択対象へ自動追加し、理由を表示する。「この日を戻すと、個別に削除していない記録も表示されます」と選択時に伝える。親の日の選択を外すと、その親が必要な記録も選択から外す。日だけを選んでも、個別に削除した子の記録まで自動復元はしない。

復元は親の日を先に処理し、その成功を確認してから子の記録を処理する。既存の単件 mutation を使い、同時実行数を制限して対象ごとに結果を管理する。成功した対象は一覧と選択から除き、失敗した対象は理由とともに選択を残す。親が失敗した記録は未復元として残す。「失敗した対象を再試行」で残りだけ処理する。実行中は二重送信を防ぎ、進捗を表示する。結果はまとめて知らせ、対象件数分のトーストを並べない。

既存の [trash.list](../../convex/services/trash/list.ts) の返却値と [validator](../../convex/lib/validators/trash.ts) に、記録の `dayId` を追加する。返却済みの削除日の `_id` と結合すれば親を特定でき、追加のデータ取得や別 query は不要。同じ日付に複数の日が存在し得るため、日付では結合しない。UI の主な変更先は [TrashList](../../src/features/trash/components/trash-list.tsx)。

ActionBar はモバイルの下端ナビと safe area の上に置き、一覧の末尾にも余白を確保する。最後の成功でバーが消えるときは、残る一覧か一覧見出しにフォーカスを戻す。永久削除は今回の一括操作に含めない。

### 4. 曜日 × カテゴリの平均学習量

履歴の分析で「週」「月」を選んだとき、既存の日別ペース・カテゴリ内訳の下、完了内訳の前に横幅全体を使って置く。「日」では表示しない。独立した分析ページや期間ピッカーは増やさず、既存の選択中の週・月に連動させる。

横軸は月曜から日曜、縦軸は集計対象日の記録に登場するカテゴリを既存内訳と同じ順で並べる。色で示す値は「その曜日1日あたりの平均分数」。確定記録だけを数え、同じ曜日の対象日数は全カテゴリで共通にする。ある日にそのカテゴリの確定記録がなければ0分とする。

計算は次の定義に従う。

`曜日・カテゴリの平均分数 = 対象日のそのカテゴリの確定分数合計 ÷ その曜日の対象暦日数`

| 日の状態 | 分子・分母への扱い |
| --- | --- |
| 選択期間内の昨日までの日 | 対象に含める |
| 休養日、確定分数のない対象日 | 0分として分母に含める |
| 今日・未来 | 分子・分母の両方から除外する |
| 利用開始前の空白日 | 除外する |
| 利用開始前でも既存の記録等がある日 | 既存の日種別の優先規則に沿って含める |
| 対象の曜日が0日 | 平均は `null` とし「対象日なし」と表示する |

例えば、対象月に月曜が5日・火曜が4日あり、あるカテゴリの確定分数が月曜100分・火曜80分なら、どちらも平均20分。記録した日だけで割らない。集計は JST の暦日で行い、表示を丸める前の値で計算する。

見出しは「曜日ごとの平均学習量」、補足は「昨日まで・休養日を含む」とし、対象期間も明示する。全セル共通で0を下限にした色の範囲を使い、凡例に分数を示す。上限は選択期間内の最大平均値に合わせるため、期間をまたぐ比較には数値を使う。0分と対象日なしは同じ表現にしない。対象期間にカテゴリがなければ、空の格子ではなく記録がない旨を表示する。

Mantine の [MatrixChart](https://mantine.dev/charts/matrix-chart/) は数値と `null` を区別できる一方、セルは読み上げ用の文字を持たない。図には説明を付け、併設する「数値で見る」で同じ平均分数・合計分数・対象日数を読めるようにする。Tooltip は補助とし、タッチやキーボードでも数値へ到達できるようにする。狭い画面で収まらない場合は図と表の領域だけ横スクロールさせる。

既存の `month.events` / `weekPage.events` を使い、`month.days` / `weekDays` の日種別から対象日を決める。親から週の記録を渡す変更と集計関数の追加で対応でき、新規 query は不要。主な変更先は [HistoryAnalysisTab](../../src/features/history/components/history-analysis-tab.tsx)、[HistoryAnalysisPanel](../../src/features/history/components/analysis/history-analysis-panel.tsx)、[scope-days](../../src/features/history/lib/scope-days.ts)。年間ヒートマップにはカテゴリ情報がないため、年間比較は今回の対象に含めない。

### 5. 予定の移動・リサイズ間隔

[Schedule drag and resize intervals](https://mantine.dev/changelog/9-6-0/#schedule-drag-and-resize-intervals) を追加の採用機能とする。移動・リサイズとも15分刻みとすることで合意済み。実装には未着手。

現行の [BoardSchedule](../../src/features/board/components/board-schedule.tsx) は `intervalMinutes`・`eventDragInterval`・`eventResizeInterval` を設定しておらず、日表示は15分、週表示は60分という Mantine のグリッドの既定値に依存している。`withEventResize` と `onEventResize` も未設定で、端をドラッグするリサイズは無効。

日・週表示の時間付き予定について `eventDragInterval={15}` と `eventResizeInterval={15}` を明示し、表示グリッドとは独立した15分刻みで移動・長さ変更を行えるようにする。移動時のゴーストプレビューも確認する。

`withEventResize`・`canResizeEvent`・`onEventResize` を接続する。対象は既に編集可能な時間付き予定とし、外部予定の編集可否・保存中・狭い画面の操作制限を引き継ぐ。移動は元の長さを保持し、リサイズは新しい開始・終了時刻を保存する。リサイズに、長さを保持する既存の移動用計算をそのまま使わない。月・年表示と終日予定は今回の間隔調整の対象外。フォームでの時刻入力も引き続き利用できる。

実装時は日・週それぞれで移動先と端の刻み、プレビューと保存結果の一致、移動時の長さ保持、リサイズ後の再表示、読み取り専用・保存中の操作制限を確認する。グリッドの `intervalMinutes` は変えず、時間枠選択による新規作成の刻みまで変更しない。

## 今回保留する機能

| 機能 | 用途と保留の理由 |
| --- | --- |
| RichTextEditor の表操作 | 教材や取り組み方の比較に使えるが、今回ユーザーが選んだのは折りたたみのみ |
| `@mantine/lightbox`・教材画像添付 | メモに添付した画像の拡大に合うが、画像の保存・表示を含む別機能。今回は保留 |
| `GaugeChart` | 週間ターゲットを1件大きく見せる用途。現在の複数ターゲットには既存の Progress が適する。習得には達成率の分母がない |
| `WaffleChart` | カテゴリ構成比の DonutChart 代替候補。割合の図を重ねて増やす必要はない |
| `CandlestickChart` | 始値・高値・安値・終値に対応するデータがない |
| AreaChart `type="stream"` | 構成の変化には使えるが、分数の読み比べが難しくなる |
| ScatterChart 右 Y 軸 | 現行画面で必要な比較がない |
| RichTextEditor `InvisibleCharacters` | 空白・改行の編集に困りごとが生じた場合に再検討する |
| 年表示の「+予定件数」 | 予定が多い日に有用な追加候補。今回の追加5機能とは分け、現時点では保留 |

## 追加機能の受け入れ条件

| 対象 | 確認する振る舞い |
| --- | --- |
| 履歴グラフ | 週・月、月境界、0分の選択日、範囲外の選択日で注記が正しく、既存の数値が変わらない |
| 平均集計 | 曜日が4回／5回ある月、休養日、今日・未来、利用開始前、開始前に記録がある日、対象日0日、カテゴリの0分を検証する。未着手・進行中・スキップと削除済みの記録は分子に入れない |
| MatrixChart | 週・月の選択に追従し、日では表示しない。全0分でも色の範囲が壊れず、対象日なしと区別できる。数値表が図と一致する |
| 方法メモ | 挿入・見出し／本文の編集・解除、保存後の再編集、毎回閉じた初期状態、空メモ、既存HTML、保存失敗時の内容保持を実際の editor で確認する |
| 一括復元 | 日だけ・記録だけ・親子混在・親の自動追加と解除・重複排除・同じ日付の別ID・部分失敗・親失敗・再試行・実行中の二重操作を確認する。既存の所有者チェックと復元可能期間を引き継ぐ |
| 予定の移動・リサイズ | 日・週で15分刻みになり、グリッド表示は変わらない。プレビューと保存結果が一致し、移動は長さを保持、リサイズは新しい開始・終了を反映する。編集不可・保存中・狭い画面の操作制限を守る |
| 画面操作 | 認証済みの実画面でデスクトップ／狭い画面を確認し、キーボードとタッチで操作できる。下端ナビ、safe area、横スクロール、フォーカス、トーストの積み重ねを確認する |

実装時は集計・保存往復・親子復元の振る舞いを重点的にテストする。`vp check` → `vp test` → `vp build` と React doctor を実行し、既存改善も含めて認証済みブラウザで確認する。今回の計画編集では、アプリのコード変更やこれらのテスト再実行は行わない。

## 実装済み改善の検証結果

既存の状態移動・計測・保存テストに加え、操作不可のドラッグ、セットアップの保留と順不同完了、年表示の日選択・読み取り専用予定・空の日・一覧を閉じる操作を回帰テストする。全体の `vp check`、`vp test`、`vp build`、React doctor を実行する。

認証済み実画面でのドラッグ、通知の積み重ね、各画面幅での表示は、ログイン可能なブラウザでの確認が別途必要。

実行結果：`vp check` 成功、`vp test` は249ファイル・1,500件成功、`vp build` 成功。React doctor の診断は指摘なし（スコアAPIには接続できなかった）。ビルドには依存側の `rrule` の default export と Tabler icons の大量再エクスポートに関する警告が残る。ログイン済みブラウザを操作できなかったため、実画面の目視と実際のドラッグ・通知ジェスチャーの確認は未実施。
