# 習得の学習量実績は非正規化カウンタで持ち、達成時点で凍結する

習得目標に併記する学習量の実績（目標作成日以降の確定分数と実施日数）を、読み取り時の導出から、目標ドキュメント上の保存フィールド（`confirmedMinutes` / `activeDays`）への差分更新に変える。確定状態を変えるすべての書き込み経路（記録の確定・分数編集・削除・ゴミ箱復元・日の削除/復元）が、同一トランザクション内で「作成日 ≤ 記録日」の未達成の習得目標へ差分を適用する（CVX-15）。実施日はその暦日の確定合計の 0↔正 遷移で ±1。達成済み（`achievedAt` あり）の目標は差分適用の対象外とし、達成時点の実績が凍結される。達成解除時は rows から一度だけ再計算して現在進行形に復帰し、この再計算関数がカウンタ漂流時の修復手段を兼ねる。

導出のままでは集計窓の下端（目標作成日）が固定・上端（今日）が毎日進むため、読み取り量が未達成目標の寿命に比例して単調増加し、rows への全書き込みが `goals.list` の購読を再実行させる（convex-reviewer が CVX-11 の将来リスクとして指摘）。窓を N 日で切る案は「作成以降の累積」という仕様（CONTEXT.md「習得」、ADR-0006 設計 7）に反するため不採用。非正規化の代償は「書き込み経路の網羅漏れ = 表示が静かに狂う」リスクで、経路ごとのテスト（CVX-19）と解除時再計算による修復可能性で緩和する。凍結は性能のためだけでなく意味論の要請でもある — 達成一覧は履歴であり、履歴は後の学習で書き換わらない（週間ターゲットで週次スナップショットを拒んだのと同じ無修正主義）。

## 追記

- **差分は「書き込みの後 − 前」の実測**：各経路が想定した増減を渡すのではなく、`withMasteryProgressDelta` が書き込みの前後でその暦日の確定合計を測り、その引き算をカウンタに足す。同じ暦日に日ドキュメントが複数ある状態（`collapseExtraLiveDays` が掃除する状態）でも、書き込みの実際の効果とカウンタがずれない。記録の生存判定も `rowDayLiveness` に一本化し、「暦日で引く」規則を経路間で揃えた。ゴミ箱の記録の完全削除（`purgeRow`）だけは前後どちらも実績の外であることが証明できるので実測を挟まない。
- **漂流の修復手段は到達可能**：`internal.mutations.goals.recomputeMasteryProgress`（所有者を引数に取る internalMutation）が、その所有者の未達成の習得目標すべてを rows から数え直す。達成済みは凍結された履歴なので数え直さない（復帰は達成解除だけ）。所有者ぶんの数え直しは、いちばん古い作成日から rows を一度だけ読み、各目標の起点で純関数側に絞る（目標ごとに同じ範囲を読み直さない）。
- **再計算の読み取り量は許容する（CVX-11）**：再計算は目標作成日から現在までの生きた記録を1トランザクションで全部読むので、読み取り量は目標の寿命とともに単調増加する。実行されるのは達成解除（`setAchieved` の `achievedAt` 省略）とカウンタ修復だけの低頻度操作で、所有者1人の本アプリでは許容範囲と判断した。将来ここが肥大化したら期間チャンク化（または達成時点のスナップショット保持）を検討する。
- **バックフィルは不要**：習得タイプの目標ドキュメントはどのデプロイにも存在しない（dev で確認、prod は習得タイプの導入前）ため、`activeDays` / `confirmedMinutes` を必須フィールドとして追加してよい。
