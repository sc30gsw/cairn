# カレンダー購読フィードを廃止し、Google カレンダーとの双方向同期に置き換える

`docs/specs/calendar-feed.md`（#76）で決めた capability-URL 型の .ics 購読フィードは、反映が各カレンダーの取得間隔
（最大24時間）に依存し、外部の予定をアプリで見る手段も無かった。所有者が求めているのは「空き時間を見ながら予定を置き、
カレンダー側で動かした結果もアプリに戻る」体験なので、購読フィード（`calendarFeedTokens`・`/calendar/*.ics`・
`lib/ics.ts`・マイページの購読 URL）を**完全に撤去**し、Google Calendar API を所有者の Google アカウント
（[ADR-0016](./0016-google-login-replaces-notion.md)）で叩く双方向同期に替える。Apple / Outlook への個別出力は失う
（必要なら Google 側の共有で賄う）。Notion カレンダーには API が無く、接続した Google アカウントの予定を表示する製品
なので、Google に書けば Notion カレンダーにも出る。

**出すもの**: 進行中の本番の本番日・未達成チェックポイントの期限（終日・空き）、予定ブロック（時刻つき・予定あり）。
書き込み先は接続アカウントのメインカレンダー（`primary`）。**戻すもの**: 予定ブロックは移動・時間変更・削除をすべて
アプリに反映する（記録は残る）。本番日・期限は Google 側の日付変更だけ反映し、Google 側で消されても目標は消さず次の同期で
予定を復元する（目標にはゴミ箱が無く不可逆なので、削除はアプリからだけ）。**外部予定**（アプリが作っていない Google の
予定）は予定タブの日・週ビューに薄く並べ、アプリからの移動・削除は Google に反映する。作成・題名の編集・記録への紐づけは
しない。表示するカレンダーは所有者が一覧から選ぶ。写しは過去 30 日〜未来 90 日。

**仕組み**: アプリ → Google は目標・予定のミューテーション内で `ctx.scheduler.runAfter(0, internal…)` を積み、内部
アクションが差分（upsert / delete）を送る。Google → アプリは `events.list` の syncToken 差分同期で、予定タブを開いた
とき・「今すぐ同期」・1時間ごとの cron で取る。push 通知（`events.watch`）は webhook のドメイン所有確認が Google 側で要る
ため v1 では使わず、後から足せる構造にする。どの目標・予定がどの Google イベントかは対応表テーブルで持つ（Google の
クライアント指定 ID は base32hex 限定で Convex の `_id` を使えない）。両側でほぼ同時に変えたら後の更新が勝つ
（Google の `updated` とアプリの更新時刻を比較）。スコープは `calendar.events` + `calendar.calendarlist.readonly`。
連携解除時はアプリ発の Google イベントと、アプリが持つ外部予定の写し・対応表を消す。トークン失効はマイページに
「再接続が必要」を出して同期を止める（通知欄には出さない）。

**Considered Options:** 購読フィードと併存させる案（同じ予定が二重に見え、2系統の保守が残る）、アプリ専用の副カレンダー
に書く案（最小権限だが、所有者は普段のカレンダーに直接載せたい）、Notion データベースにも書く案（Notion カレンダーは
Google アカウント接続が前提で、Notion トークンは8時間で失効・3 req/s の制限があり、2系統目の価値が薄い）、
一方向のまま API 書き込みにする案（外部予定が見えず、空き時間の確認ができない）、Google が常に勝つ／アプリが常に勝つ
競合規則（説明はしやすいが、片側の編集が黙って消える）。

**Consequences:** `CONTEXT.md` の「逆同期」Avoid は撤回し、何が戻るかを「カレンダー同期」「外部予定」で定義した。
外部予定は学習量・消化・週間ターゲット・レビュー・共有文のどれにも数えない。予定ブロックの Google 側削除がアプリの予定
を消すので、予定タブから消えた理由が「カレンダーで消した」である場合がある。Google の OAuth 同意画面に Calendar の
sensitive スコープが入る。
