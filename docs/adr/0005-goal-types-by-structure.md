# 目標タイプは内容でなく構造で切る。試験・ペース・達成量・習得・その他の固定5値

目標の入力欄はタイプごとに変わる（discriminated union、コード駆動）。分類軸は「試験勉強か健康か」という内容領域ではなく、進捗の構造（期限日に一度だけ結果が入る / 期間ごとにリセットされる / 期限まで積み上げる / 数値を持たない）。内容領域ではこのアプリの目標は全件が学業に潰れて判別子にならない（Austin & Vancouver 1996; Google Calendar Goals の失敗例）。習慣ゴールはペースに畳み、マイルストーン型は採らない（週境界が既に均等配置の締切として機能し、細分化は持続性を下げる — Ariely & Wertenbroch 2002; Rai et al. 2023）。6枠目は意図的に空け、第1候補はマイルストーン型。タイプは所有者が追加できない固定一覧で、`~domain` のタプルが Convex validator・Valibot・UI の単一の真実。達成量タイプの単位（分・ページ・問題・回・冊）も同じ理由で所有者が拡張できない固定タプル（`VOLUME_UNITS`）とする。根拠: [docs/research/goal-type-taxonomy.md](../research/goal-type-taxonomy.md)

## 改訂（2026-08-17 同日）

タイプを 試験 / 習得 の固定2値に縮小し、ペース・達成量・その他を削除した。判別子は判定の入り方（試験: 外部の期限日に一度だけ結果が入る / 習得: 自己判定でいつでも達成にできる）で、「構造で切る」原則は不変。「いつまでに何ができているか」は期限つき習得（チェックポイント）が担い、マイルストーン型は今回も新設しない — 期限の有無だけで型を増やさない。ペースの頻度ノルマは週間ターゲットへ、達成量は習得の can-do 文または週間ターゲットの件数へ畳む。詳細は [ADR-0006](0006-checkpoints-replace-weekly-goals.md)。
