# ボードの移動は確認モーダルなし・3種 Toast

実行ボードのカンバンから確認モーダルを全廃する。ドラッグ・カードメニュー・ボタンによるすべての状態遷移は即実行し、
結果は次の3種の Toast だけで知らせる: 確定（`進行中 → 確定` / `未着手 → 確定`）は「学習時間 XX分を記録しました」、
計測破棄（`進行中 → 未着手` / `進行中 → スキップ` で計測あり）は「計測 XX分を捨てました」、確定解除
（`確定 → 未着手`）は「確定を取り消しました」。これ以外の遷移（`未着手 → 進行中`、計測なしの `pause` / `skip`、
`確定 → 進行中` の再開など）は silent とする。エラー Toast は出さない — mutation が失敗すれば楽観更新した表示が
reactive query によって元の状態へ巻き戻るので、その巻き戻り自体が唯一のフィードバックになる。計測破棄の Toast に
Undo は無い。捨てた計測は戻せず、必要なら改めて計測を開始する。

ボードの確認モーダルとして最後まで残すのは、分数が無く計測もない記録を確定列へ動かしたときにだけ開く確定エディタ
（`needsKanbanConfirmEditor`: `minutes === 0 && 計測なし`）のみである。これは「何を確定したか確認する」ための
モーダルではなく、「入力が無いと0分で確定してしまう」ことを防ぐための入力要求であり、性格が異なる。

**Considered Options:** 学習量へ影響する操作すべてに確認モーダルを維持する案、確認モーダルは無くすがすべての遷移で
Toast を出す案、確認モーダルを全廃し学習量が変わる操作だけ Toast にする案（採用）。

**Consequences:** カンバン上の移動は原則ノーモーションで完了し、計測を持つ記録の見送り・未着手戻しは確認なしに
即座に不可逆へ進む。分数が無い記録の確定だけは引き続きその場で入力を求める。ADR-0011 が定めた「表面（画面）ごとに
Confirm の有無を分ける」方針そのものは維持する — 日ページの見送り Confirm・見送り取消 Confirm はこの ADR の対象外
で従来どおり残る。変わるのはボード面だけで、そこにあった Confirm を Toast に置き換えた。
