# カレンダー接続の追加で Cairn へのログイン権限を与えない

所有者は個人用 Google アカウントで Cairn にログインしている。仕事用などの追加 Google アカウントを接続する目的は、そのカレンダーを実行ボードで確認することであり、Cairn のログイン手段を増やすことではない。カレンダー接続は追加アカウントにログイン権限を与えず、既存の個人用 Google ログインは維持する。

[ADR-0016](./0016-google-login-replaces-notion.md) の `linkSocial` による連携をそのまま複数アカウントへ広げると、追加アカウントも同じ所有者としてログイン可能になる。実装の単純さよりも、カレンダーへのアクセス許可と Cairn へのログイン権限を分けることを優先する。接続の追加・再認可・解除によってログイン権限を変更しない。

この区別は認証処理でも守り、ログイン画面に追加アカウントを表示しないだけの実装にはしない。2案の実装を比較し、Better Auth の既存トークン保管・更新と provider／session の拡張点を使う案を採用した。所有者・期限・対象を持つ認可要求を OAuth state と照合し、Google subject ごとのログイン方針をアカウント保存前と session 作成前に検証する。方針は接続解除後も保持する。認証ライブラリや OAuth の実装は置き換えない。設計候補と検証条件は [multiple-google-calendars.md](../specs/multiple-google-calendars.md) に残す。
