# 本番目標は結果で終了し、進行中は1件のまま履歴化する

本番目標（試験タイプ）に結果欄 `result = { score, recordedAt }` を任意で持たせ、結果が入った本番目標を「終了」とする。
進行中 / 終了の判別は結果の有無だけで、目標タイプは増やさない（ADR-0005「構造で切る」を維持。終了は判定の入り方が
変わったのではなく、その判定が入ったという状態）。「本番目標は1件だけ」は「進行中は1件だけ」に改める。結果が入ると
次の本番目標を作れるようになり、終了した本番は達成した目標（習得の達成履歴）と同じ場所に本番バッジ付きで並ぶ。
結果は1本番につき1値で、訂正はできるが取り消しはできない。

未達成の子チェックポイントは親が終了してもそのまま残す。残っている間は終了した本番もツリーに残り（達成済みだが
未達成の子が残る長期目標と同じ除外条件）、子の編集で次の本番や長期目標へ付け替えられる。終了した本番の下に新しい
チェックポイントは足せない。

**Considered Options:** 本番後は本番目標を上書きして使い回す案（履歴が残らず、カウントダウンの軸が本番ごとに
消える）、「終了した試験」を別タイプにする案（ADR-0005 に反し、validator・UI・型の三重化）、結果を別テーブルに
時系列で持つ案（Avoid「模試スコアの系列をアプリに入れること」に踏み込む）、結果は一度だけで訂正不可にする案
（入力ミスの救済が「削除して作り直す」しか無くなる）、終了時に未達成の子を自動で長期目標に戻す・次の本番に自動で
付け替える案（所有者の意図を推測して構造を変えてしまう）。採用したのは、結果欄を任意で持たせて有無で終了を判別し、
訂正のみ許し、子は残して手で付け替える案。

**Consequences:** `goals` の試験の枝に `result` が増え、`create` の1件判定・`update` の引き継ぎ・DTO・ツリー構築・
親候補・マイページの本番検索が「進行中の本番」を見るようになる。終了した本番は削除しない限り残るので、履歴の件数は
本番の回数分だけ増える。結果の取り消しは提供しない。セットアップの完了条件「本番目標がある」は変えない（初回
セットアップの意味で、終了後に Stepper を再表示しない）。
