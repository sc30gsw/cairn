# Project Structure

> This rule extends [CODING_GUIDELINES.md](../CODING_GUIDELINES.md) §Project Structure.

## Feature layout

```
convex/
├── schema.ts               # Single source of truth for the data model (CVX-16)
├── auth.ts / auth.config.ts / http.ts   # Convex Auth framework files — not domain content, stay flat
├── crons.ts                # Cron definitions — must reference internal.* functions only, never api.* (CVX-05)
├── queries/<domain>/       # Public queries, one file per function (client-facing API — CVX-20)
├── mutations/<domain>/     # Public mutations, one file per function (client-facing API — CVX-20)
├── actions/<domain>/       # Actions, one file per function ("use node" isolated to its own file — CVX-06)
├── services/<domain>/      # Business logic (ctx-based, CVX-02) + pure functions (CVX-09), one file per function
├── lib/                    # Cross-cutting only, NOT split by domain: requireUser/requireSelf, JST date helpers, shared validators (CVX-16)
└── _generated/             # Auto-generated by the Convex CLI — NEVER edit manually

src/
├── features/          # Business logic — one module per domain
│   └── [feature]/
│       ├── api/       # Query/mutation wrappers around Convex functions
│       ├── components/
│       ├── hooks/
│       ├── schemas/   # Valibot schemas
│       └── types/     # Type definitions (derived from convex/_generated types)
├── routes/            # TanStack Router file-based routing (minimal logic)
├── router.tsx         # ConvexQueryClient integration — wires TanStack Router to Convex
├── lib/
│   └── theme.ts
└── styles.css
```

There is no separate ky-based REST client or OpenAPI-generated SDK. Convex client integration lives entirely in `src/router.tsx` (`ConvexQueryClient`) plus the auto-generated `convex/_generated` directory.

`src/components/`, `src/hooks/`, `src/utils/` are created on demand when something is genuinely shared across features.

See `docs/spec.md` §2 and `.claude/rules/convex-rules.md` (CVX-20) for the full reference layout and domain breakdown (`users`, `partnerStatus`, `dashboard`, `correlations`, etc.).

## `~` alias (relative paths forbidden)

> Also enforced by PostToolUse hook in `.claude/settings.json`

```typescript
// CORRECT
import { useProducts } from "~/features/products/hooks/use-products";
import type { Product } from "~/features/products/types/product";

// WRONG: relative paths — forbidden even within the same directory
import { useProducts } from "../hooks/use-products";
import { helper } from "./helper";
```

## Feature inter-dependencies forbidden

```typescript
// WRONG: feature importing directly from another feature
// src/features/orders/components/order-form.tsx
import { UserSelect } from "~/features/users/components/user-select";

// CORRECT: extract to src/components/
import { UserSelect } from "~/components/user-select";
```

## Routes exception

Route files (`src/routes/**/*.tsx`) use `export const Route = createFileRoute(...)`. The oxlint `no-default-export` rule is overridden for this path in `vite.config.ts`.

```typescript
// src/routes/products.tsx — named export is sufficient, no default export needed
export const Route = createFileRoute("/products")({
  loader: ({ context: { queryClient } }) =>
    queryClient.ensureQueryData(getProductsOptions({ query: { limit: 20 } })),
  component: ProductsPage,
});
```
